# План портирования Liquid Glass в веб-интерфейсы (WebGL2 / WebGPU / Chromium CSS+SVG)

> **статус:** архитектурный и инженерный план (без реализации кода в репозитории). Цель — адаптировать текущий clean-room конвейер (`GLSL 440` / `Qt RHI`) для UI-компонентов веб-приложений при бюджете **<= 1.0–1.8 мс/кадр на GPU** и **0 мс на idle**, сохранив доступность DOM, выделение текста и корректный фолбэк в браузерах без нужных API.

---

## 1. Главная техническая проблема веба (почему CSS `backdrop-filter` не хватает)

В отличие от нативного оконного композитора, браузерный `backdrop-filter: blur(...)` работает по фиксированному графу эффектов и не даёт шейдерного доступа к подложке (backdrop) произвольных DOM-элементов:

1. **Ограниченный `backdrop-filter: blur()`** — даёт размытие и `saturate()`, но не умеет:
   - нелинейное преломление краёв по SDF-фаске (`convexBevelProfile` / Снеллиус);
   - хроматическую дисперсию на границе;
   - многозонный блур по глубине от края (`sampleMultiBandBackdrop`).
2. **Chromium `backdrop-filter: url(#svgGlass)`** — единственный кросс-DOM способ в чистом HTML без WebGL: через SVG `<feImage>` (запечённая 2D-карта смещений нормалей) + `<feDisplacementMap>` искажать пиксели *под* HTML-элементом.
   - *Минусы:* работает не во всех движках (Firefox и Safari исторически не поддерживают или режут `backdrop-filter: url(#...)`), 8-битное квантование карты смещений даёт лесенку при большом `scale`, а 3-канальная дисперсия требует отдельных проходов/фильтров с резким падением FPS.
3. **HTML-in-Canvas (Chromium Origin Trial `canvas-html`)** — эксперимент Chromium для рендеринга живого DOM-поддерева прямо в WebGL-текстуру без `html2canvas`-костылей. На момент составления плана находится за флагом / Origin Trial (`not production cross-browser baseline`), поэтому не может быть единственным механизмом для публичного web app.

Отсюда следует практическая архитектура: **разделить фон ("сцену") и поверхностный DOM-слой**, а сам шейдер облегчить в 4–6 раз относительно десктопного полного прохода.

---

## 2. Три варианта архитектуры для веб-приложений

### Вариант A (рекомендуемый для UI-приложений): Scene-Backed WebGL2 Overlay + прозрачный DOM

Подходит для дашбордов, плееров, лендингов, веб-ОС, редакторов и любых SPA (React/Vue/Svelte/Vanilla), где под стеклянными панелями находятся обои, градиенты, 2D/3D-канвасы, графики, изображения или видео.

```text
[ Живая сцена (Canvas / WebGL2 Background Layer) ]
        │
        ├─ dirty? ──(нет)──► пропуск рендера (0 мс GPU idle)
        │
        └─ (да) ─► 3-уровневая мип-пирамида (1/2 -> 1/4 -> 1/8) в clampUV
                        │
                        ▼
[ Единый батч glass-панелей поверх сцены ] ◄── ResizeObserver + IntersectionObserver (DOM rects)
                        │
                        ▼
[ Настоящий прозрачный DOM (кнопки, текст, a11y, focus, aria) ]
   └─ @supports fallback для low-power / без WebGL: backdrop-filter + oklch градиент + drop-shadow()
```

**Почему это работает лучше всего в проде:**
- Весь текст внутри стеклянных карточек остаётся нативным DOM — идеальный субпиксельный антиалиасинг шрифтов, выделение мышью, `Tab`-навигация, экранные дикторы и SEO/формы без `canvas` текста.
- Отрисовка всех стеклянных виджетов на экране идёт **за 1 instanced draw call** (массив rect/radii/tint параметров в UBO `std140` или `texelFetch`-буфере).
- Если пользователь не скроллит и не двигает карточки/фон — `requestAnimationFrame` не запускает проходы пирамиды вообще (**dirty-flag invalidation**, как в хороших оверлейных рендерерах).

### Вариант B (Zero-WebGL / локальный прогрессивный эффект): Baked SVG `<feDisplacementMap>` + Modern CSS Fallback

Для статичных дизайн-систем и контентных страниц поверх произвольного scrollable HTML (включая чужие DOM-узлы с текстом под панелью):
- В CSS-фолбэке для всех браузеров задаётся базовый слой:
  - `backdrop-filter: blur(...) saturate(...)`
  - Градиенты фаски/подсветки с явным `in oklch` / `in oklab` (равномерная воспринимаемая яркость без «грязных» серых провалов в середине градиента sRGB).
  - Тени для непрямоугольных силуэтов/капель через `filter: drop-shadow(...)` вместо `box-shadow`.
  - Бликовые `mix-blend-mode` слои строго внутри `isolation: isolate`, чтобы не ломать z-stacking всей страницы.
- Для Chromium-движков прогрессивно навешивается предрасчитанная процедурная карта нормалей (procedural squircle displacement map в base64/canvas blob) -> `<feImage>` + `<feDisplacementMap>` в `@supports (backdrop-filter: url(#glass))`.

### Вариант C (полный перенос нашего конвейера): WebGPU WGSL + Compute JFA

Для 3D-вьюеров, Figma-подобных холстов, видеоредакторов и WebGPU-приложений:
- Текущие `build/spv/*.spv` (Vulkan SPIR-V) транслируются в `WGSL` через `naga` / `tint` (или переписываются 1-в-1 на `WGSL`, структура UBO идентична `std140`).
- **Главный выигрыш относительно WebGL2:** JFA (`jfa_seed` + `jfa_step`) переносится в **Compute Shader с `var<workgroup>` тайлами 16x16**, что сокращает число round-trip проходов глобальной памяти, а 13-tap `downsample_clamped` читает соседние тексели из shared memory 1 раз вместо 13 глобальных выборок.

## 3. Оптимизация и «облегчение» шейдеров под веб (Web Lite Profile)

Текущий clean-room фрагментный шейдер (`liquid_glass_panel.frag`) ориентирован на полную физическую/визуальную точность на дискретном GPU: внутри него вызывается `sampleMultiBandBackdrop` (3 зоны глубины * 7 спектральных тапов = **до 21 текстурной выборки** плюс ещё **7 тапов** на `bleedSample` — суммарно до **28–29 чтений текстуры на каждый пиксель панели**, даже в плоском центре!).

Для веб-интерфейсов (ноутбуки, мобильные GPU, 4K HiDPI экраны с `devicePixelRatio = 2`) нужен **Web Lite Profile**, который визуально неотличим на UI-панелях, но **сокращает стоимость на 75–88%**:

| Узел конвейера | Полная нативная версия (`shaders/`) | Оптимизированный `Web Lite Profile` | Экономия |
|---|---|---|---|
| **Ветвление по зонам SDF** | Считает полную 3-band + 7-tap дисперсию даже в центре карточки | Раннее отсечение (tiering) по `d`: вне тени/bleed -> ранний выход; в плоском центре -> без дисперсии и bleed | **-70–80% выборок текстуры** по площади |
| **Спектральная дисперсия** | 7-tap цикл `spectralTapWeight(0..6)` на каждый band | **3-tap RGB split** (`[-1, 0, +1] * dispDelta`) *только* в узком кольце фаски (`hLens > 1e-3`) | **7 тапов -> 3 тапа** (и **0 тапов** в центре) |
| **Многозонный блур** | 3 вызова `sampleBackdropDispersed` на каждый пиксель (`band A/B/C`) | 1–2 аппаратных `textureLod` вдоль радиальной кривой глубины (без вложенной дисперсии на глубоком blur-слое) | **3x -> 1x** по bandwidth |
| **Аналитический Squircle SDF** | 3 вызова `pow(..., 4.5)` на пиксель + 4x finite difference градиент | При фиксированном стиле (`smoothness = 1.0`, `p = 4`): быстрая степень без `pow()`, градиент аналитический (без 4x повторения SDF) | **~4x меньше ALU**, ноль `pow()` на ветвях |
| **Мип-пирамида даунсэмпла** | 5 мипов с 13-tap clamped box filter (по 13 выборок) | **3 мипа (`1/2, 1/4, 1/8`)**: для UI-степени размытия (8–24 CSS px) хватает 3 уровней с аппаратной билинейкой (5-tap Karis/Kawase вместо 13-tap) | **-60% pass time** на фоне |
| **JFA маска -> SDF + нормали** | Полный проход на каждый кадр, если форма меняется | Аналитика для всех карточек/кнопок/пилюль; JFA **только на ресайз/смену маски** с кешем в атлас | **0 мс/кадр** на статичной геометрии |
| **Преломление 3D Снеллиуса** | Попиксельный ray-trace + TIR на весь экран | Только для выделенных линзовых капсул/луп по tight bounding quad | Устраняет overdraw пустых пикселей |

### Деталь по тирингу (Early-Out по расстоянию `d`) в `Web Lite`
В интерфейсе 80%+ площади крупной карточки занимает плоский центр (`-d > bevelWidth`). Разделение на 4 узкие ветки резко разгружает мобильные тайловые GPU (Apple Silicon / Adreno / Mali):
1. `d > max(bleedWidth, shadowRadius)` — снаружи: мгновенный `return vec4(0.0)` (или рисование tight-quad ровно по габариту виджета + shadow apron вместо полноэкранного прохода!).
2. `d > 0.0` (зона тени / внешнего отблеска) — считаются только `evalShadowFalloff` + опциональный `outerBleedProfile`, **без** тяжёлого interior grading / bevel spec.
3. `-bevelWidth < d <= 0.0` (активное кольцо фаски 12–28 px) — единственное место, где нужны `convexBevelProfile`, `3-tap` хроматическая дисперсия, `evalBevelHighlight` и `evalCosineRimGlow`.
4. `d <= -bevelWidth` (плоское «тело» панели) — здесь `hLens == 0` и `dispDelta == 0`: хватает **ровно 1** `textureLod` на нужном mip-уровне + `faceMatrix` (1 матрица 3x4) + `huePreservingClamp`. Ни дисперсия, ни `gradPanelComposite`, ни `bleedSample` тут физически не меняют цвет пикселя.

## 4. Технические детали WebGL2 GLSL ES 3.00 vs GLSL 440

При переносе шейдеров из `shaders/*.frag` в WebGL2 (`#version 300 es`) потребуются четыре системных адаптации:

1. **Единый сэмплер + mipmaps в WebGL2:**
   - В GLSL ES 3.00 поддерживается `textureLod(sampler2D, uv, lod)` на текстурах с полным мип-стеком (`gl.texStorage2D` + FBO по mip-уровням через `framebufferTexture2D(FRAMEBUFFER, COLOR_ATTACHMENT0, TEX, lvl)`).
   - **Важно про текстуры:** для Half-Float (`RGBA16F`) мип-пирамиды и линейной интерполяции обязательно проверить/активировать расширение `EXT_color_buffer_float` (или использовать `RGBA8` с декодированием sRGB -> Linear вручную: в `RGBA8` теряется HDR > 1.0 headroom для `huePreservingClamp`, зато `RGBA8` гарантированно рендерится и фильтруется 100% устройств, включая бюджетные смартфоны -> `HDR` включать по capability-тесту!).
2. **Std140 UBO vs Uniform-буферы в WebGL2:**
   - UBO поддерживается в WebGL2 нативно (`layout(std140) uniform`), но для батчинга `N` виджетов за 1 вызов удобнее передавать массив экземпляров (`struct GlassInstance`) через UBO фиксированного размера (например, 32 панели на батч = `~6–8 КБ`, вписывается в минимальный лимит 16 КБ спецификации WebGL2).
3. **Защита от преумножения и композитинг с HTML:**
   - HTML5 `<canvas>` по умолчанию композитится браузером как **premultiplied alpha** (`premultipliedAlpha: true`). Выход clean-room оверлейного режима (`compositeBackdrop = 0.0`) уже соблюдает инвариант `rgb <= alpha`, но на WebGL2 нужно убедиться, что цвет фона канваса очищается в `(0, 0, 0, 0)` и блендинг установлен как `ONE, ONE_MINUS_SRC_ALPHA`.
4. **Adaptive DPR (Dynamic Pixel Ratio):**
   - Для фоновой мип-пирамиды достаточно рендерить base-pass с `dpr = min(devicePixelRatio, 1.5)` или даже в `0.5x` от физического экрана: стеклянный фон всё равно размыт через mip-уровни, поэтому даунскейл пирамиды до 0.5x глазом не виден, а экономит **75% fill-rate** на 4K/Retina экранах. Панельную фаску и антиалиасинг (`fwidth(d)`) при этом нужно крутить в полном нативном DPR экрана, чтобы блики на кромке оставались звенящими и чёткими.

## 5. Пошаговая дорожная карта внедрения (Phase 1 -> Phase 4)

### Phase 1: Ядро `Web Lite` + CPU/GPU валидация (GLSL ES 3.00)
- Вынести из `liquid_glass_panel.frag` облегчённый профиль (`3-tap` RGB dispersion, аналитический градиент squircle без `pow`, строгий `4-tier` early-out).
- Добавить проверку визуальной дельты (`Delta-E` / PSNR) между полной десктопной версией (`build/render_preview.png`) и `Web Lite` на стенде `tests/egl_render_test.c`.
- **Критерий приёмки:** потеря качества < 1% в кольце фаски, <= 4 texture fetches в центре панели, 0 предупреждений валидаторов.

### Phase 2: Scene-Backed WebGL2 Runtime & Dirty Scheduler
- Лёгкий zero-dependency TS-рантайм (< 15 КБ gzip): управление `SceneCaptureFBO` + 3-уровневый clamped mip-pyramid + батчинг до 32 панелей за 1 draw call.
- Подписка на `IntersectionObserver` (пауза невидимых виджетов), `ResizeObserver` и dirty-флаг перерисовки сцены (0 мс CPU/GPU в статике).
- **Критерий приёмки:** 120 FPS на 10 одновременно анимируемых стеклянных карточках на встроенном GPU (1080p/1440p), 0% GPU при простое.

### Phase 3: DOM Accessibility Bridge & CSS/SVG Fallback Matrix
- Синхронизация позиций прозрачных DOM-контейнеров с WebGL quad-ами перед paint (один readback геометрических rect в начале кадра -> без layout thrashing).
- Многоуровневый graceful degradation:
  1. `Tier 1 (WebGPU / WebGL2 RGBA16F)` — полная `Web Lite` оптика + HDR clamp.
  2. `Tier 2 (WebGL2 RGBA8 / Low-Power)` — SDR `Web Lite` + пониженный DPR пирамиды.
  3. `Tier 3 (No-WebGL / prefers-reduced-transparency)` — чистый CSS (`backdrop-filter`, `in oklch` подсветка кромки, `filter: drop-shadow()`) с сохранением контраста текста WCAG AA.

### Phase 4: Опциональный Progressive Bridge для Arbitrary DOM
- Исследование SVG `<feDisplacementMap>` для Chromium без фонового WebGL-холста и отслеживание стабилизации Chromium `canvas-html` без Origin Trial как будущего унифицированного источника DOM-подложки.

## 6. Сводка рисков и ограничений

| Ограничение | Влияние | Митигация |
|---|---|---|
| **Нет доступа к arbitrary HTML под стеклом (Firefox/Safari)** | WebGL не видит текст других `<div>` без перерисовки | Размещать подложку в WebGL/Image/Video/Canvas-сцене или использовать SVG/CSS fallback |
| **Cross-origin `<video>` / `<img>` (CORS taint)** | `texImage2D` падает с SecurityError без CORS | Обязательный `crossorigin="anonymous"` + fallback на чистый CSS |
| **Контекст-лосс WebGL (`webglcontextlost`)** | Чёрные карточки на вкладках в фоне / при перезапуске драйвера | Автовосстановление буферов/шейдеров + мгновенное переключение в CSS fallback до восстановления |
| **`RGBA16F` фильтрация/блендинг на старых мобильных GPU** | Возможный откат или отсутствие линейного фильтра float texture | Детект `EXT_color_buffer_half_float` / `OES_texture_float_linear` на старте + `RGBA8` фолбэк |
